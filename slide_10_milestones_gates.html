Milestones & Gates

Khái niệm & mục đích

Milestone = mốc tiến độ • Gate = cổng chất lượng

  • Milestone: mốc đo/đếm được để đóng tiến độ (ví dụ: Scope Freeze, Design Freeze, Feature Complete).
  • Gate: cổng ra–vào chất lượng trước khi đi tiếp; đòi hỏi work products & QA evidence đạt tiêu chí.
  • Khác biệt: Milestone trả lời “đã xong cái gì”, Gate trả lời “đủ tốt để đi tiếp chưa”.
  • Gắn chặt với chuỗi Task set → Work products → QA → Milestones để tăng minh bạch & khả kiểm chứng.
Gate criteria

Đo được • Quan sát được • Kiểm toán được

  • Đầu vào: artefacts/bằng chứng phải có (thiết kế, threat model, SAST/DAST, test report, SBOM, signatures…).
  • Tiêu chí kiểm: checklist/metrics (0 High/Critical; coverage ≥ X%; action items đã xử lý).
  • Kết quả: Go / No‑Go / Risk Accepted (có owner & hạn).
  • Qua gate ⇒ mới đóng milestone liên quan. Evidence nên được gom tự động về Evidence Store.

Gates được đặt sau các giai đoạn phù hợp; quyết định Go / No‑Go / Risk Accepted dựa trên evidence đã tích luỹ.
Ví dụ dàn mốc

M1 • M3 • M4 — Định nghĩa Done

  • M1 Scope Freeze: SRS/BRD gọn; NFR sơ bộ (hiệu năng, bảo mật, khả dụng, quan sát, tuân thủ); traceability REQ-* khởi tạo.
  • M3 Design Freeze: ADR, data model, API contract qua SDR; threat model cập nhật; liên kết REQ → ADR/API.
  • M4 Feature Complete: code & tests đạt ngưỡng; Bug Bar 0 Critical/High; SBOM & chữ ký artefact; PR liên kết REQ-*.
Secure SDLC overlay

Các gate bảo mật tiêu biểu

  • SDR: review thiết kế (trust boundaries, AAA, hardening); xác nhận biện pháp có test kèm theo.
  • Bug Bar: ngưỡng ship‑worthy tại Feature Complete (0 Critical/High; Medium có mitigation & lịch).
  • FSR: tổng hợp evidence (review notes, test results, SBOM, signatures, audit logs) để Go/No‑Go/Risk Accepted.
